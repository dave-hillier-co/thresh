# Orleans port analysis

A faithfulness review of every `@thresh/*` package against its corresponding subsystem in the Orleans reference source (`~/repos/orleans/src`). Generated by a multi-agent workflow on 2026-05-28 (19 agents, ~10m, 1.7M tokens). The structured raw output lives in the task transcript referenced below; this document is the human-readable distillation.

## Executive summary

**Overall verdict: beta-credible.**

The TypeScript port is a substantively faithful re-implementation of Orleans' core semantics — single-threaded turns, single-activation via directory CAS, ETag persistence, timestamp-ordered 2PC, durable journaling and jobs, Kubernetes-native membership — with deliberately documented deviations and a strong sociable/TDD test discipline. It is credible for non-trivial single-region deployments today.

Several production-grade gaps keep it short of full Orleans parity and pose real correctness risks under failure and overload:

- No cancellation tokens or request deadlines anywhere in the call chain
- Scheduler has no back-pressure (unbounded queues, no stuck-turn or `onDeactivate` timeout)
- Sparse runtime instrumentation (OTel surface exists; most meters are not wired)
- Serialization codec has no versioning, polymorphism, cycles, `Map`/`Set`, or surrogate types
- Stream pulling agents have no `IStreamFailureHandler` (head-of-line blocking on a permanently-failing handler)
- Transaction locks have no deadline; in-doubt 2PC recovery is one-shot

## Top gaps (highest impact across the whole port)

1. **Cancellation tokens and request deadlines end-to-end.** Orleans threads `CancellationToken` through every call and deactivation. The TS port has none. Hung methods, slow downstreams, and shutdown paths cannot be interrupted, undermining liveness and graceful drain. Prerequisite for several other items below.
2. **Scheduler back-pressure.** Per-activation queues are unbounded, there is no `MaxRequestProcessingTime` stuck-turn detection, and no force-kill on hung `onDeactivate`. One misbehaving grain can consume memory or block silo shutdown indefinitely.
3. **Runtime instrumentation breadth.** `@thresh/observability` provides meters and tracing seams, but the runtime (catalog, directory, persistence, messaging, reminders, streams) does not emit them. Operators have no visibility into activation latency, storage tails, directory hit rates, or message flow.
4. **Serialization versioning and polymorphism.** The 6-tag value codec silently degrades unknown types to plain objects with no versioning. Blocks safe rolling upgrades, third-party types, and event-sourcing payloads.
5. **Stream `IStreamFailureHandler` and producer registration.** A permanently failing subscriber causes infinite head-of-line redelivery on a shared queue; there is no policy to fault, unsubscribe, or back off.
6. **Transaction lock deadlines and TM confirmation-worker keepalive.** Stalled transactions hold locks forever; in-doubt prepared records on remote participants are only resolved once on activation, leaving durability gaps after TM crashes.
7. **Grain observers / client callbacks and grain extensions.** No typed observer surface and no `IGrainExtension` mechanism means push notifications, cancellation tokens, and management/system-target APIs cannot be expressed.
8. **`StatelessWorker` enforcement.** The option is parsed but never honored. Multi-activation-per-key placement (a major Orleans throughput pattern) is effectively absent.
9. **Directory hardening.** Missing versioned range locks, ACK'd snapshot handoff, dead-silo lookup checks, and crash-broadcast recovery. Best-effort one-shot recovery can lose entries or return stale pointers under rapid view changes.
10. **Reminders robustness.** No minimum-period validation, no initial-load retry, no `GetReminder(s)` API, no boot gating. Silent `.catch(()=>undefined)` in reconcile/fire hides operational issues.

## Detailed findings per package

### `@thresh/core`

Faithful: grain identity `(type, key)` with stable hash, single-turn enforcement, lifecycle hooks, ETag-based persistent state, durable journaling facets (`DurableValue`/`Dictionary`/`List`), transactional state with 2PC and timestamp ordering, reducer pattern with event folding, grain references as runtime `Proxy`, reentrancy controls (`@reentrant`, `readOnly`, `alwaysInterleave`), implicit subscriptions, reminders, durable jobs, migration via dehydrate/rehydrate, grain call filters, placement strategies (random, prefer-local, activation-count, silo-role, resource-optimized).

Intentional deviations (per `docs/deviations.md`): runtime ES `Proxy` for references (not codegen), `@serializable` registration (not source-gen), WebSocket transport, per-activation `TurnScheduler` mechanism, K8s as membership authority, pod-name+UID identity, factory closures (`defineGrain`) alongside the class form.

Missing Orleans features: `IGrainExtension`, `MayInterleave` predicate, `StatelessWorker` enforcement, `IGrainObserver`, `IGrainService`, `ClientObserversPlacement`, `GrainCancellationToken`, version-compatibility framework (`AllVersionsCompatible`/`BackwardCompatible`/`StrictVersionCompatible`), grain-to-client callbacks, system-target grains.

Risks: `stateless` option parsed but never honored; `@readOnly` not enforced at runtime; value codec is ad-hoc `$thresh`-tagged and not cross-language interop; `keyKindOf` is runtime-inferred with no static guarantee.

### `@thresh/runtime`

Faithful: turn scheduler with Orleans-style reentrancy semantics; activation state machine (`creating`/`activating`/`valid`/`deactivating`/`invalid`); per-activation FIFO queue; catalog by grain ID; directory CAS for single-activation; idle-collection deactivation; stream/broadcast delivery as system extensions; grain timers cleared on deactivate; request-context propagation via `AsyncLocalStorage`; placement strategies and version-aware pre-filtering.

Gaps: no `CancellationToken` through the call chain; no deactivation timeout (`cts.CancelAfter(DeactivationTimeout)` in Orleans); no `MaxEnqueuedRequestsSoftLimit`/`HardLimit`; no stuck-activation detection (`MaxRequestProcessingTime`); no system targets or management grain; simplified `DeactivationReason` (no enumerated codes); rejection types collapsed into a `kind` string; no per-activation `IServiceScope`; no `IGrainLifecycle` observable events.

Risks: unbounded `turn-scheduler.ts:44` queue; `activation.ts:218-220` schedules `onDeactivate` with no timeout; stream delivery silently drops when handler absent (`activation.ts:290-291`); dehydration does not carry pending requests forward; orphaned timers if `deactivate()` throws before `timers.clear()`.

### `@thresh/messaging`

Faithful: message envelope with correlationId, direction, target/sending grain and silo, interface ID and method, body; three directions (request/response/oneWay) and three response kinds (success/error/rejection); request-context headers (trace, transaction, baggage); `ConnectionPreamble` with protocolVersion, siloAddress, clusterId; correlation matching with timeout; per-peer duplex connection pooling; system-message routing.

Intentional deviations: WebSocket vs Orleans TCP+custom framing; flag set simplified (no `IsReadOnly`/`IsAlwaysInterleave`/`IsUnordered`/`IsLocalOnly`/`IsKeepAlive`/`TimeToLive`/`RetryCount`/`ForwardCount`/`CacheInvalidationHeader`); body always `Uint8Array` (no in-memory short-circuit path); `GrainInterfaceType` omitted; runtime `@serializable` + MessagePack default.

Unintentional gap flagged: no `TimeToLive` or retry/forward counts. Messages can hang indefinitely if a response is lost; caller times out but no resend or expiration.

Risks: WebSocket `send()` not explicitly ordered under concurrent sends; correlation key uses `bigint.toString()` (theoretical wrap collision); no back-pressure (inbound buffers grow); `InProcessTransport.deliver()` throws synchronously if endpoint absent; preamble ACK is a single `1` byte with no auth.

### `@thresh/directory`

Faithful: consistent hash ring with virtual nodes; deterministic ring construction; CAS register for single-activation; partition ownership routed by hash; ring-based range ownership with handoff/drop classification; location cache with per-silo invalidation; stale-view detection with bounded retry.

Intentional deviations (driven by K8s as SSOT): no per-range versioned locks or `WaitForRange` barriers; handoff is best-effort pull (no ACK-deletion loop); no crash-initiated broad recovery; transport-agnostic `DirectoryPeer` instead of system-target RPC.

Risks: `beginRecovery` (`cluster-node.ts:616-639`) silently ignores pull failures (`catch` block); activation can register while successor's recovery is still pulling; lookup returns stale pointer if the silo is dead but not yet cleaned (`local-directory-partition.ts:18`); handoff snapshot retained indefinitely if successor crashes pre-pull (`cluster-node.ts:219`); concurrent writes during `drain` and `acceptHandoff` are not locked.

Missing Orleans features: versioned range locks; partitioned snapshot transfer with ACK and tombstone cleanup; crash-recovery broadcast; `recoveryMembershipVersion` tracking; multi-silo partition split handling.

### `@thresh/clustering-k8s`

Faithful: K8s as authority; EndpointSlice watch replacing membership table; ready endpoint condition as failure detector; pod-name+UID identity; stable ring key across restarts; grace-period drain before removal; versioned membership snapshots.

Intentional deviations: 4-state `SiloStatus` (`joining`/`active`/`draining`/`dead`) collapsing Orleans' 8; read-only membership interface (no `TryKill`/`TrySuspect`); no gossip; no active probe-graph.

Gaps: no `TryKill`/`TrySuspect`; no version-target `Refresh(minimumVersion)`; **no active peer probing** — a silo that passes readiness but hangs on calls is undetectable; no membership cleanup-on-restart; local status transitions (draining) not visible in the snapshot.

Risks: watch disconnection creates a blind spot until reconnect (default 1s); `KubernetesMembership` always includes `localSilo` even when not in slices (a silo can never observe itself as not-a-member); readiness probe is single point of failure for FD; pods in `Terminating` may linger in DNS for seconds; watch reconnect interval is fixed 1000ms.

### `@thresh/hosting` — faithful

Faithful: silo lifecycle (start/stop with membership-driven recovery); single-threaded turns with Orleans reentrancy; persistent and transactional state facets mirroring `IPersistentState<T>`/`ITransactionalState<T>`; graceful drain on SIGTERM (readiness flip before stop); directory CAS register and cache invalidation; idle collection; distributed dispatcher with placement and version filtering; reminder registry; durable-job execution with concurrency limiting and slow-start; stream providers (memory and Redis pulling agents) with at-least-once; broadcast channels; grain call filters; OTel seams; activation rebalancer; K8s membership.

Intentional deviations: no `IServiceCollection`/DI container (bespoke fluent builder); standalone `SiloHost` (no `IHostedService` integration); MessagePack default; K8s liveness/readiness probes via HTTP endpoints; minimal configuration validation surface.

Gaps: no `IConfigurationValidator` extension point; no `IStartupTask`/grain-service equivalent; no internal scheduler/queue perf counters; turn scheduler not swappable.

### `@thresh/client`

Faithful: pluggable gateway list providers (static, membership, URL); round-robin selection and failover; timeout-based failure detection; per-gateway dead marking with refresh recovery; correlation by ID; grain references as runtime `Proxy`; one-way calls; MessagePack default.

Gaps: no grain observer callbacks (`CreateObjectReference<T>()`); no DI integration; no W3C trace-parent or request deadline propagation; only `markAsDead()` (no `MarkAsUnavailableForSend` distinction); no connect-retry backoff or `MINIMUM_INTERCONNECT_DELAY` (Orleans waits 100ms between attempts); no per-grain client-side connection pinning via bucket array (intentional — relies on silo-side turn ordering); `rehydrate()` requires pre-registered grain types (no manifest fallback).

Risks: `GatewayManager.next()` counter is not protected by a lock — concurrent `Promise.all` callers can race; `client-node.ts:131-176` invoke loop spins forever on empty gateway list; no backoff between fast failures; single `callTimeoutMs` covers the whole failover loop; missing grain type throws instead of fetching manifest.

### `@thresh/persistence`

Faithful: `IPersistentState` contract (read/write/clear); ETag-based optimistic concurrency for all writes/clears; `StateHolder { value, etag, exists }` mirroring `IGrainState`; multiple named states per grain; blind-write rejection; default-value factory for non-existent state; `InconsistentStateError` on etag mismatch; storage provider abstraction; pluggable multi-provider registry; migration via dehydrate/rehydrate; reducer-state snapshot persistence; value codec; single-activation enforced by runtime.

Intentional deviations: in-memory provider uses a counter ETag (dev only); Redis and Postgres providers use UUID v4; cluster-shared backends instead of `MemoryStorageGrain`-style sharding; serialization via value-codec, not `IGrainStorageSerializer`; `structuredClone()` for mutation isolation in the memory provider.

Gaps: no wildcard ETag (`*`) for unconditional overwrite; no storage-grain recovery mitigation (null-currentETag path); no null-etag bypass for `clear`; no `CancellationToken` on read/write/clear; no batch state operations; minimal provider configuration surface.

Risks: serialization errors during read propagate as plain errors, not `InconsistentStateError`; counter-based memory ETag could collide if the provider is reset (dev-only); reducer snapshots lose partial in-memory raises if the grain crashes between `raise()` and `write()`.

### `@thresh/reminders`

Faithful: single-activation delivery via `RemindableInterface.receiveReminder`; hash-range ownership with `readRange(hashBegin, hashEnd)`; durable upsert with fresh ETag and CAS removal; failover recovery via range reconciliation; fixed-rate rescheduling (rearmed before callback); one-shot cleanup after firing; idempotent reconciliation; three backends (memory, Redis Lua, Postgres `ON CONFLICT`).

Gaps: no `LocalSequenceNumber` conflict detection; no minimum-period validation (DOS vector via misconfigured high-frequency reminders); no initial-load retry with backoff; no `GetReminder`/`GetReminders` query APIs; no service-ready boot gating on register/unregister.

Risks: `.catch(()=>undefined)` in reconcile and fire paths silently swallows errors — lost ticks are invisible.

### `@thresh/streams`

Faithful: pulling-agent model; cursor; implicit subscription via attribute; at-least-once delivery semantics.

Gaps: no `IStreamFailureHandler` (no configurable fault/skip policy, no exponential backoff); no batch container; no explicit producer registration.

Risk: a permanently failing handler in `queue-pulling-agent.ts` redelivers forever and blocks every other subscriber multiplexed on the same queue — a head-of-line stall with no escape.

### `@thresh/transactions`

Faithful: timestamp-ordered wait-die locking; 2PC with prepare/commit/abort; durable in-doubt recovery on activation; participant enlistment; cascading abort semantics.

Gaps: no lock deadlines (a hung holder blocks all conflicting transactions until the grain deactivates); no TM confirmation-worker keepalive (in-doubt records resolved only once on activation); no one-phase read-only commit optimization; no reentrancy detection.

Risks: `reader-writer-lock.ts` `enter()` waits indefinitely; `transactional-state-impl.ts` `recover` runs once with no retry — if the TM is unreachable at activation time the record stays in-doubt silently.

### `@thresh/journaling`

Faithful: append-only log; CAS versioning; replay on activation; snapshot compaction.

Gaps: no `DurableQueue`/`DurableSet`; no field retirement / schema migration mechanism; no lifecycle hooks for journaled state; no pluggable codec.

### `@thresh/durable-jobs`

Faithful: sharded at-least-once delivery; shard adoption on rebalance; poison-pill protection; retry with backoff; `pollAfter` scheduling.

### `@thresh/observability` — partial

Faithful: OTel tracing surface; W3C `traceparent` propagation; meter and exporter wiring.

## Cross-cutting findings

### Single-threaded turn invariant

The per-activation `TurnScheduler` correctly enforces single-turn execution around `await`. The risk is not the scheduler itself but the absence of safeguards: any `Promise.all` over user-supplied promises, any timer or callback scheduled outside `scheduleAsync`, and any external library that resumes on a different microtask queue can violate the invariant silently. The scheduler should at minimum assert that resumed continuations belong to its own queue when running in dev.

### Single-activation under K8s membership

CAS at the directory provides the correctness backstop. The window of concern is during view changes: both silos may construct `ActivationData` before the CAS arbitrates, leaving the loser to idle-collect rather than tear down immediately (`distributed-dispatcher.ts deliverLocal`, `catalog.ts activateLocal`). Combined with watch-reconnect blind spots and the lack of dead-silo checks on lookup, the practical risk is brief duplicate processing under rapid pod churn. Mitigation: add a "loser-tears-down-now" path on CAS-lose, and check `IsSiloDead(targetSilo)` in `lookup`.

### Serialization

The value codec uses a 6-tag scheme with `$thresh` markers. Unknown types silently round-trip as plain objects; there is no schema version, no polymorphism resolution, no `Map`/`Set` support, and no circular-reference guard. Rolling upgrades that add fields are not safe in general — they depend on application-level handling. This is the single biggest blocker for safe production schema evolution.

### Test discipline

Sociable tests exist across packages and exercise real grains through real schedulers, consistent with the project's classic-TDD stance. Coverage is thinner on failure paths: deactivation under load, recovery on directory failure, network drop during dispatch, and TM crash during 2PC. An Orleans-`TestingHost`-equivalent harness for fault injection would close most of the remaining test-discipline gap.

## Roadmap alignment

`EPICS.md` positions the port at Orleans 10 parity. The "Shipped" list is broadly consistent with what the per-package analyses confirm as implemented (actor model, multi-silo messaging, DHT directory with lossless range handoff, K8s membership, persistence, timers/reminders, streams, ACID transactions, durable journaling, migration, interface versioning, broadcast channels, call filters, observability seams, external client, durable jobs, activation rebalancer). The remaining "Designed" item (browser state replication) is explicitly beyond parity.

The synthesis surfaces parity-relevant gaps that `EPICS.md` does not currently list as in-flight:

- Cancellation and per-call deadlines
- Scheduler back-pressure, stuck-turn detection, deactivation timeout
- Runtime instrumentation breadth
- Serialization versioning and polymorphism
- Stream failure handlers
- Transaction lock deadlines and TM keepalive
- Grain observers and extensions
- `StatelessWorker` enforcement

Observability is listed as Shipped but is partial; the status board should reflect that.

## Recommendations (ordered)

1. **Add cancellation and per-call deadlines** through the dispatcher, turn scheduler, and deactivation path. This is the single largest correctness gap and a prerequisite for several other items (TM cancel, deactivation timeout, stream redelivery backoff).
2. **Harden the turn scheduler**: bounded per-activation queue with soft/hard limits, `MaxRequestProcessingTime` stuck-turn detection, and an enforced `onDeactivate` timeout that force-invalidates the activation.
3. **Instrument the runtime** (catalog, directory, persistence, messaging, reminders, streams) with the OTel meters already wired in `@thresh/observability`, and add `exception.type`/`message`/`stacktrace` attributes to spans. Closes the production-observability gap.
4. **Introduce a versioned, registry-based serializer** with surrogate types, polymorphism, `Map`/`Set`, circular-reference handling, and per-field version tags. Required for safe rolling upgrades and event-sourced payloads.
5. **Add stream `IStreamFailureHandler`** with configurable fault/skip policy and exponential backoff; add explicit producer registration. Eliminates head-of-line blocking.
6. **Add transaction lock deadlines** with cascading abort, and a confirmation-worker that periodically pings remote TMs to resolve in-doubt prepared records.
7. **Tighten the directory**: check silo liveness on lookup; expire retained handoff snapshots; retry recovery pulls with backoff; track a `recoveryMembershipVersion` to gate concurrent registers.
8. **Enforce `StatelessWorker` placement** and add runtime `@readOnly` mutation checks (at least in dev mode).
9. **Add grain observers / typed client callbacks** and a minimal `IGrainExtension` mechanism. Unblocks push notifications and is a prerequisite for system-target style APIs.
10. **Fix reminders**: enforce minimum period; gate register/unregister on service-ready; retry initial load; propagate fire/remove errors with logging; add `GetReminder`/`GetReminders`.
11. **Tighten the client**: atomic gateway counter; retry backoff between fast failures; per-attempt timeout instead of cumulative; manifest fallback for unknown grain types. Add per-job `RunId` deduplication in `@thresh/durable-jobs`.
12. **Update `EPICS.md` and `todo.md`** to reflect the parity gaps surfaced here — particularly that observability is partial and that cancellation, back-pressure, serialization versioning, stream failure handling, TM keepalive, observers, extensions, and `StatelessWorker` remain before an Orleans 10 parity claim. Keeps the status board honest per the project's evergreen-docs convention.

# ADR 0001 — Runtime ES `Proxy` grain references

- Status: Accepted. The runtime-`Proxy` decision stands; the **numeric method-table / `methodId` wire
  mapping below is superseded by [ADR 0009](0009-message-dispatch-substrate.md)** — calls now
  dispatch by method name and an interface declares no method table.
- Context doc: [02 — The actor model](../02-actor-model.md)

## Context

Orleans grain references are strongly-typed proxies generated by a C# source generator at compile
time: calling a method on a reference constructs a request object and dispatches it. TypeScript has
no equivalent first-class compile-time code generator in the standard toolchain. We need a way to
turn `await counter.increment(5)` on a typed interface into a message, while keeping references
lightweight and serializable.

Options considered:

1. **Runtime ES `Proxy` + decorators.** A `getGrain<T>()` returns an ES `Proxy` whose traps turn
   method calls into request envelopes, using a method table registered via a decorator/helper.
2. **Build-time codegen** (e.g. ts-morph / a compiler plugin) producing proxy classes from
   interfaces, mirroring Orleans closely.
3. **Hand-written / decorator-registered stubs** with no `Proxy`.

## Decision

Use **runtime ES `Proxy` plus decorators** (option 1).

The type parameter `T` on `getGrain<T>(def, key)` provides full compile-time type safety to callers.
The `Proxy` provides the runtime dispatch. A `defineGrainInterface` helper (or `@grainInterface`)
records a stable, ordered method table that assigns each method a numeric id for the wire protocol.

## Rationale

- **Idiomatic and build-step-free.** No extra generator to run, wire into builds, or keep in sync;
  the developer writes a normal `interface` and a one-line method-table registration.
- **Type safety where it matters.** Callers get full IntelliSense and checking through the generic
  parameter; the dynamic part is confined to the dispatch boundary.
- **Lightweight, serializable references.** A reference carries only `GrainId` + interface id; the
  `Proxy` is reconstructed on deserialization. This matches Orleans' lightweight-reference property.
- **Fits the rest of the design.** The same registration approach (decorator-recorded metadata)
  drives serialization type tags ([04](../04-messaging-and-serialization.md)) and grain registration
  ([02](../02-actor-model.md)), so there is one consistent mechanism rather than a codegen step for
  references and something else for everything else.

## Consequences

- **Numeric method ids come from the registered method table, not method names.** Reordering the
  `methods` array is a breaking wire change; the array is treated as an append-only ordered contract
  (documented for implementers).
- **Wire-shape mistakes surface at runtime, not compile time** (e.g. a method missing from the
  table). Mitigated by a startup validation pass that checks every grain interface has a complete,
  consistent method table, and by tests.
- **`Proxy` has a small per-call overhead** versus a generated class. Negligible relative to network
  and serialization costs for remote calls; for hot local calls the dispatcher can bypass the proxy.
- **Decorator metadata mode must be pinned** consistently across packages
  (see [12](../12-project-structure-and-tooling.md)).
